### 3. Security P0 fixes

- **SEC-008** — `/api/moderate-message` + `/api/moderate-photo` were
  reachable anonymously. Both now call `requireUser()` + are rate-limited
  by `userId:ip` key (moderate-message = 60/min, moderate-photo = "strict"
  limiter since each call burns 100-300kb Sightengine quota).
- **SEC-005** — dropped `'unsafe-eval'` from CSP `script-src`. Next 16
  production builds no longer need it. `'unsafe-inline'` stays until we
  wire nonce-based CSP through `proxy.ts`.
- **SEC-016** — `Permissions-Policy` extended from 2 entries to a full
  OWASP 2026 deny list. Only geolocation + camera granted to (self),
  everything else explicitly denied.

### 4. CPO quick wins

- **CPO-001** — welcome slide lied with "14 modes de rencontre" after
  Wave 15 cut the catalog to 4 core modes. Fixed title + grid 4→2 cols.
- **CPO-003** — `/map` profile pins were `Math.random()`-placed around
  city center AND re-shuffled per render (ghost walking). Now:
  - Deterministic FNV-like hash of profile id → stable pseudo-random
  - Jitter reduced to ~500m aligning with target SEC-001 grid snap
  - Honest trust banner: "Positions floutées à ~500m pour ta sécurité"
- **CPO-002** — `/browse` geoloc refused → dedicated CTA state instead
  of misleading "C'est tout pour ce soir" empty state. Exposes the real
  OS message + link to /help.

### 5. Safety-critical

- **CR-005** — `getCurrentPosition()` in the SOS missed-check-in pipeline
  had no `.catch`. Mobile Safari geoloc denial would bubble as unhandled
  rejection and silently break the SMS dispatch loop. Defensive catch
  falls back to placeholder position so contacts still get the alert.

### 6. Route type casts (build unblock)

Next 16 made `<Link>` and `router.push()` strictly typed against the
generated `routes.d.ts` union. 13 sites in the codebase build dynamic
hrefs from strings — each now has `import type { Route } from "next"`
+ `as Route` cast where the href is genuinely runtime-built. Proper
"Route-typed props everywhere" migration is tracked as follow-up.

## Deferred to follow-up PRs

Ranked by priority. Full findings in `.claude/saas-audits/2026-04-24-cesoir-glowup/`.

### P0 — need user review (high risk)

- **SEC-001** — profiles.location SELECT is `USING (true)` for all auth
  users, `nearby_profiles` RPC returns `ST_X/ST_Y` to 7 decimals (~1cm).
  Stalking-vector. Fix: new migration 024 creating `public_profiles`
  view that excludes raw location + grid-snap 500m in the RPC. Requires
  a Supabase migration + RLS changes — high-blast-radius.
- **SEC-004** — `user_blocks` doesn't filter profile SELECT. Blocked
  users still see victim location / online status / avatar. Blocking is
  client-side cosmetic only. Requires RLS refactor.
- **SEC-006 / SEC-007** — `signUp` and `resetPasswordForEmail` called
  client-side with no rate limit. Email-bomb + account enumeration
  vectors. Fix: wrap both in `/api/auth/forgot-password` + `/api/auth/signup`
  server routes with rate-limit + CAPTCHA.
- **SEC-011** — `face-api.js` drags `node-fetch@<2.6.7` (CVSS 8.8).
  Needs removing face-api.js entirely or SelfieVerification refactored
  onto nsfwjs-only. Product-level decision first.

### P1 — architectural

- **CR-001 / CR-002** — two god files (`chat/[id]/page.tsx` 1104 LOC,
  `IceBreakerGame.tsx` 1636 LOC). Extract sub-components.
- **CR-003** — N+1 in `useConversations` (4 sequential queries per
  realtime event). Fix with a `conversations_with_meta` Postgres view.
- **R-001 / R-010** — adopt Cache Components + Data Access Layer (multi-week
  migrations tracked for a future sprint).
- **CTO-push** — `NEXT_PUBLIC_PUSH_SUBSCRIPTION_URL` absent in prod,
  push notifications silently dropped.
- **CTO-roses** — rose refill countdown stored in `localStorage`,
  falsifiable. Needs server-side clock.

### P2 — polish / next sprint

- `typedRoutes: true` migration with proper Route-typed props
- 41 `any` usages (one major — `SupabaseClient<any>` in api/auth.ts)
- 15 `TODO WAVE-16` comments to triage
- Storybook coverage 22% → 80%
- Remove `src/lib/trust-colors.ts` + `src/lib/verification-status.ts`
  (their consumers were deleted in this PR, but the hook blocked the
  git rm for those two specific filenames — they'll get swept next pass)
