## 3. Numerama — Angle "Tech stack & B2B SaaS"

**Sujet mail** : "Une dating app qui se finance par les bars — stack et modèle"

Bonjour [PRÉNOM],

**CeSoir** est une app de rencontre française qu'on a lancée sur un modèle
B2B SaaS inversé : les _users_ ne payent rien, les _bars_ payent pour
apparaître dans la rubrique Soirées (pricing pin-by-pin, facturation CB
mensuelle).

**Stack technique** :
- Frontend : Next.js 16 (PWA installable, pas de React Native)
- Backend : Supabase (Postgres + RLS + Realtime + Storage + Auth)
- Deploy : Vercel Edge, frontière EU
- Monitoring : Sentry + PostHog
- B2B monétisation : Stripe Checkout (actuellement feature-flaggée OFF, user-side désactivée)

**Métrique business** :
- Launch-gate : invite-only, 3 codes par user, scarcity manufacturée
- Beachhead : Montpellier, 10 bars ciblés en Wave 1
- Unit économique : ~50€/mois par venue featured, 5 slots featured/semaine/ville
- Objectif 6 mois : 25 venues B2B clients, expansion Lyon + Bordeaux

Le papier qui m'intéresserait : "Comment une dating app française **refuse la
monétisation user** — et monte un modèle alternatif à ce que font Meta/Match".

Dispo pour interview + démo dashboard B2B si sujet vous parle.
