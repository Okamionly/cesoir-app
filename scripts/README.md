# scripts/

Operational scripts for cesoir-app. Run with `npx tsx scripts/<file>.ts` (TypeScript) or `node scripts/<file>.mjs` (JavaScript).

---

## setup-stripe-products.ts

Provisions the 7 CeSoir products + prices in Stripe (Test mode by default) and prints the resulting `price_xxx` IDs as an env-var block ready to paste into Vercel. Replaces the `price_REPLACE_ME_*` placeholders in `src/lib/stripe/plans.ts`.

The catalog is read directly from `src/lib/stripe/plans.ts` so the script and the runtime cannot drift.

### What gets created

| Internal id        | Name (Stripe)                | Amount        | Type       |
| ------------------ | ---------------------------- | ------------- | ---------- |
| `premium_monthly`  | CeSoir Premium Mensuel       | 9.99 EUR/mo   | Recurring  |
| `premium_annual`   | CeSoir Premium Annuel        | 59.99 EUR/yr  | Recurring  |
| `roses_5`          | CeSoir Bouquet               | 2.99 EUR      | One-time   |
| `roses_15`         | CeSoir Jardin                | 6.99 EUR      | One-time   |
| `roses_30`         | CeSoir Roseraie              | 9.99 EUR      | One-time   |
| `boosts_3`         | CeSoir Pack Starter          | 3.99 EUR      | One-time   |
| `boosts_10`        | CeSoir Pack Pro              | 9.99 EUR      | One-time   |

> Note: the audit task description mentioned a different price grid (4.99/49/1.99/etc). The script honors the **single source of truth** in `src/lib/stripe/plans.ts`. To change prices: edit `plans.ts` first, then re-run the script — it will create new price objects (with new IDs) and archive the old active ones on each product.

### Run it

#### Test mode (default — recommended)

```bash
# 1) Get your test secret from https://dashboard.stripe.com/test/apikeys
# 2) Run the script
STRIPE_SECRET_KEY=sk_test_xxx npx tsx scripts/setup-stripe-products.ts
```

You will see something like:

```
▶ CeSoir Premium Mensuel — 9.99 EUR/month
  + created product   premium_monthly      prod_QXXXXXXX
  + created price     premium_monthly      price_1QXXXXXXX
…

──────────────────────────────────────────────────────────
 Done. Paste these into Vercel env vars (or .env.local):
──────────────────────────────────────────────────────────

# Generated by scripts/setup-stripe-products.ts (TEST mode)
STRIPE_PRICE_PREMIUM_MONTHLY=price_1Q…
STRIPE_PRICE_PREMIUM_ANNUAL=price_1Q…
STRIPE_PRICE_ROSES_5=price_1Q…
STRIPE_PRICE_ROSES_15=price_1Q…
STRIPE_PRICE_ROSES_30=price_1Q…
STRIPE_PRICE_BOOSTS_3=price_1Q…
STRIPE_PRICE_BOOSTS_10=price_1Q…
```

#### Live mode (real money — KYC required)

```bash
STRIPE_SECRET_KEY=sk_live_xxx npx tsx scripts/setup-stripe-products.ts --confirm-prod
```

Without `--confirm-prod` the script refuses to run with `sk_live_` to prevent accidents.

### Idempotency

Re-running the script is safe. It looks up existing products by `metadata.cesoir_product_id` (the stable internal id from `plans.ts`) and re-uses them. For prices it matches on `(amount, currency, recurring.interval)` and only creates a new price if no active match is found. Older active prices are archived (Stripe doesn't allow deleting prices, but archived prices stop appearing in lookup).

### Idempotency caveat

If you change a price in `plans.ts` (e.g. 9.99 → 12.99), the script will:

1. Re-use the existing product (same `cesoir_product_id`).
2. Create a brand new `price_xxx` with the new amount.
3. Archive the old active prices on that product.

You then need to update `STRIPE_PRICE_*` in your env (Vercel + `.env.local`) with the new id. Existing active subscriptions on the old price keep billing at the old amount until cancelled or migrated — Stripe's intentional design.

## Wiring the price IDs into Vercel

After running the script, copy the env-var block it printed and add the variables on Vercel:

```bash
# Per-variable (interactive)
vercel env add STRIPE_PRICE_PREMIUM_MONTHLY production
vercel env add STRIPE_PRICE_PREMIUM_ANNUAL production
vercel env add STRIPE_PRICE_ROSES_5 production
vercel env add STRIPE_PRICE_ROSES_15 production
vercel env add STRIPE_PRICE_ROSES_30 production
vercel env add STRIPE_PRICE_BOOSTS_3 production
vercel env add STRIPE_PRICE_BOOSTS_10 production
```

Or via the dashboard: Vercel project → Settings → Environment Variables → Add for `Production` (also add to `Preview` and `Development` if you want preview branches to use the same Stripe test products).

You also need these Stripe secrets (separate concern — not generated by this script):

| Var                                  | Where it comes from                                                  |
| ------------------------------------ | -------------------------------------------------------------------- |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | https://dashboard.stripe.com/test/apikeys (`pk_test_…`)             |
| `STRIPE_SECRET_KEY`                  | same page (`sk_test_…`) — server-side only                          |
| `STRIPE_WEBHOOK_SECRET`              | Webhook endpoint signing secret (see below)                         |
| `STRIPE_ENABLED`                     | Set to `"true"` to satisfy `isMonetizationEnabledServer()`           |
| `SUPABASE_SERVICE_ROLE_KEY`          | Already configured for other features — webhook needs it            |

After adding env vars, **trigger a redeploy** (Vercel doesn't auto-redeploy on env var change in all plan tiers).

## Registering the webhook on Stripe Dashboard

The script doesn't register the webhook — that has to happen on the dashboard once the app is deployed:

1. Go to https://dashboard.stripe.com/test/webhooks (or `/webhooks` for live).
2. Click **Add endpoint**.
3. Endpoint URL: `https://<your-vercel-domain>/api/stripe/webhook` (e.g. `https://cesoir-app.vercel.app/api/stripe/webhook`).
4. Select these 7 events to listen on:
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `customer.subscription.trial_will_end`
   - `invoice.paid`
   - `invoice.payment_failed`
   - `payment_intent.succeeded`
5. Click **Add endpoint**.
6. Copy the **Signing secret** (`whsec_xxx`) and add it to Vercel as `STRIPE_WEBHOOK_SECRET`.
7. Re-deploy.

For local dev: `stripe listen --forward-to localhost:3000/api/stripe/webhook` prints a `whsec_` you put in `.env.local`.

## Don't forget — Customer Portal

Stripe requires the Customer Portal to be activated on the dashboard before `stripe.billingPortal.sessions.create()` can be called by `/api/stripe/portal`:

1. https://dashboard.stripe.com/test/settings/billing/portal
2. Click **Activate test link** (or the live equivalent).
3. Enable: update payment method, cancel subscriptions (at period end), view billing history.
4. Save.

Without this, the portal route returns 500.
