## 1. GTM Motion Diagnostic

**Motion actuel : Product-Led Growth pur, sans engine d'acquisition.**

CeSoir a fait le bon choix tactique pour un lancement beta : gratuit, friction minimale (3 étapes signup-quick vs 12 anciennes), géolocalisation automatique, mode activé immédiatement. C'est du PLG classique — le produit lui-même doit générer l'usage et l'acquisition.

Le problème : PLG pur sans réseau ne fonctionne pas pour un dating app. Tinder, Bumble, Hinge ont tous lancé avec une stratégie de seeding manuel (campus par campus, quartier par quartier). L'effet réseau négatif — trop peu d'utilisateurs = pas de match = churn immédiat — tue les apps dating avant qu'elles atteignent la masse critique.

Montpellier a ~300 000 habitants, ~60 000 étudiants (Université Paul Valéry + UM + Sup de Co). La masse critique pour un dating app géo-local est estimée à 500-1 000 utilisateurs actifs simultanés dans un rayon de 5 km. En dessous : désert de matches, en dessous encore : désinstallation dans les 48h.

**Verdict :** Le GTM doit être hybrid PLG + community-seeding pendant la phase beta. PLG pur = mort par manque de densité.

## 2. Landing Page Audit

**Points forts identifiés dans le code :**

- Hero "Personne ne dîne seul ce soir à Montpellier" : copy fort, géo-ancré, émotionnel. Le "ce soir" crée l'urgence — différenciateur réel vs Hinge ("designed to be deleted") ou Tinder (gamification).
- CTA "Je rejoins →" : simple, pas de friction lexicale. Lien vers `/signup-quick` qui promet "30 secondes, pas de photo, pas de bio". Cohérent.
- Sub-hero "Gratuit. Près de chez toi. Pour de vrai." : les 3 objections adressées en 6 mots. Bien vu.
- Preuve "Pas de paywall. Jamais." avec lien `/why-free` : gère l'objection de méfiance.

**Points critiques manquants :**

- **Zéro social proof sur la landing.** La page premium affiche "1,247 membres premium" (chiffre hardcodé). La landing n'a aucun chiffre, aucun témoignage, aucun badge presse. Pour une app dating locale, le premier signal de confiance c'est "X personnes à Montpellier utilisent déjà" — même si c'est 87 en beta.
- **Zéro meta tags SEO ni OG image.** La page `page.tsx` ne contient aucun `export const metadata`. Aucune balise title, description, og:image. Résultat : partage WhatsApp/Instagram = lien nu sans preview. Coût : 0€ à corriger, impact direct sur les partages viraux.
- **La landing est un SPA cinématique non-scrollable.** 3 scènes auto-play, zéro contenu texte indexable par Google. Crawlers reçoivent une page vide (PlasmaOcean en `ssr:false`, StarField idem). Le SEO local "rencontre Montpellier" est impossible avec cette architecture.
- **"Je rejoins" n'indique pas l'effort.** Ajouter "(30 sec)" dans le CTA ou juste en dessous réduit l'anxiété du clic. Micro-friction psychologique mesurable.
- **La navigation "Se connecter" est en `white/70`** sur fond sombre — correct en contraste mais elle vole l'attention versus le CTA principal. Hiérarchie visuelle à creuser.

## 3. Pricing & Monetisation

**État actuel : MONETIZATION_ENABLED = false. Revenue = 0€.**

La structure Stripe est correctement conçue :
- `premium_monthly` : 9,99€/mois, 7 jours d'essai
- `premium_annual` : 59,99€/an (~5€/mois), save 50%, recommandé
- Shop : roses (2,99€ / 6,99€ / 9,99€) + boosts (3,99€ / 9,99€)

**Benchmark concurrent (France, mai 2026) :**

| App | Entry | Premium |
|---|---|---|
| Tinder | Gratuit | 15-31€/mois |
| Bumble | Gratuit | 13-30€/mois |
| Hinge | Gratuit | 18-37€/mois |
| **CeSoir** | **Gratuit** | **9,99€/mois** |

CeSoir est positionné 30-50% sous Tinder et Bumble. C'est une erreur de positionnement pour une app qui prétend être premium et différenciée. À 9,99€/mois, tu te bats sur le prix avec Tinder au lieu de te battre sur la valeur.

**Recommandation pricing :**

Maintenir le gratuit (PLG, acquisition) mais restructurer le premium :
- **Free** : 10 likes/jour, 1 rose/semaine, chat illimité, 3 modes
- **CeSoir+ à 12,99€/mois** (pas 9,99€) : likes illimités, voir qui t'a liké, mode invisible, boost 1x/semaine, passport Montpellier → France
- **CeSoir+ Annual à 79,99€/an** (~6,67€/mois, save 48%) : idem + badge exclusif + Crystal Ball priority
- **Roses pack** : garder tel quel, les micro-transactions sont saines

Le delta 9,99€ → 12,99€ sur ~500 abonnés = +18 000€ ARR supplémentaires sans changer une ligne de code produit.

**Trigger activation monétisation :** 1 000 utilisateurs actifs mensuels à Montpellier. En dessous, la paywallisation ralentit la croissance réseau sans générer assez de revenue pour être significatif.

**Channel 3 — Partenariats restos/bars**

"Dîner ce soir à Montpellier" est dans le nom du produit. Les restos ont intérêt à apparaître comme partenaires (trafic additionnel). Proposition : QR code "Table pour CeSoir" à l'entrée → landing page co-brandée → signup. 10 restos × 50 scans/semaine = 500 tops-of-funnel/semaine.

## 5. Conversion Funnel

**Funnel actuel (reconstruit depuis le code) :**

```
Landing → CTA "Je rejoins" → /signup-quick
  Step 1 : email + password + age + invite code (optionnel)
  Step 2 : choix mode + géoloc
  Step 3 : welcome + "Commencer à swiper"
  → /browse
```

**Taux de conversion estimés (benchmark dating apps) :**

| Etape | Taux attendu | Levier d'amélioration |
|---|---|---|
| Landing → CTA click | 8-15% | Social proof, meta preview sur partage |
| CTA → Step 1 complété | 55-70% | Déjà bon (pas de photo required) |
| Step 1 → Step 2 complété | 75-85% | Mode choice = faible friction |
| Step 2 → Step 3 | 90%+ | Quasi-automatique |
| Step 3 → First browse | 80% | Welcome clair |
| Browse → First match | 20-35% | Dépend de la densité users |
| First match → First chat | 40-60% | Streaks + notification push |
| First chat → IRL meet | 5-15% | Le Saint-Graal — Crystal Ball aide |

**Le goulot d'étranglement est la densité, pas l'UX.** Avec < 200 users actifs, "Browse → First match" s'effondre en dessous de 10% et le churn J+3 dépasse 60%. L'UX signup-quick est bonne. Le problème est amont.

## 6. Retention Loops

**Déjà câblés (points positifs) :**

- Streaks (mig 037) : engagement quotidien — classique mais efficace, Duolingo a prouvé le modèle
- Daily Crystal Ball (mig 041) : rituel quotidien, différenciateur fort vs swipe pur
- Notifications push (mig 033) : actives — à calibrer pour ne pas devenir spam

**Ce qui manque pour les 90 premiers jours post-launch :**

- **Heatmap d'activité** : montrer aux users quand les autres sont connectés dans leur zone. Crée l'FOMO et les heures de connexion synchronisées (= plus de matches).
- **Weekly Recap email** : "Cette semaine à Montpellier : X nouvelles personnes, Y en mode Solo Diner près de toi." Réactivation des users dormants.
- **Match anniversary** : J+7 après un match sans message → nudge "Vous avez 7 jours pour vous rencontrer". Urgence = valeur centrale de la brand.

## 9. Brand Positioning

**"Ce soir" est le vrai différenciateur — exploiter l'urgence systématiquement.**

| Concurrent | Promesse | Horizon temporel |
|---|---|---|
| Hinge | "Designed to be deleted" | Long terme (relation sérieuse) |
| Tinder | Swipe, match, fun | Indéfini |
| Bumble | Women make the first move | Indéfini |
| **CeSoir** | **Tu ne dînes pas seul ce soir** | **Ce soir = 24h max** |

L'horizon temporel court est une arme à double tranchant : il crée l'urgence (bon pour l'activation) mais peut signaler "hookup app" plutôt que "rencontres authentiques". La copy actuelle gère bien ça ("dîner", "convive", "foodie quest" — pas de connotation hookup).

**Le risque branding Q3-Q4 2026 :** si les users perçoivent l'app comme un Tinder local avec moins d'utilisateurs, le churn sera massif. Le positionnement "social dining" doit être renforcé dans l'onboarding et les notifications — chaque touchpoint doit rappeler que CeSoir c'est un dîner, pas un swipe game.
